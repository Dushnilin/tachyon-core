# Справочник CLI и параметров времени выполнения `tachyon-core`

Документ описывает интерфейс командной строки `tachyon-core` (v0.6.2), глобальные и локальные флаги, коды завершения, переменные окружения, обработку сигналов операционной системы и подсистему логирования.

## Общий синтаксис

```text
tachyon-core [глобальные-флаги] <команда> [флаги-команды]
```

Глобальные флаги допускается указывать как до, так и после имени команды (например, `tachyon-core -c config.json check` и `tachyon-core check -c config.json` эквивалентны). При запуске без команды выводится справка (`help`).

### Глобальные флаги

| Флаг | Альтернативная форма | Описание |
|---|---|---|
| `-c <path>` | `--config <path>`, `-c=<path>`, `--config=<path>` | Путь к JSON-файлу конфигурации. Флаг можно передавать несколько раз; если указан каталог, из него загружаются все файлы `*.json` в лексикографическом порядке. |
| `-C <dir>` | `--config-directory <dir>`, `-C=<dir>`, `--config-directory=<dir>` | Путь к каталогу с фрагментами конфигурации (`*.json`). Файлы сортируются лексикографически и объединяются. Флаг можно повторять. |
| `-D <dir>` | `--directory <dir>`, `--directory=<dir>` | Сменить рабочий каталог процесса перед выполнением команды. Влияет на все относительные пути (кэш-файл `cache.db`, локальные наборы правил, сертификаты). |
| `--disable-color` | — | Отключает ANSI-раскраску вывода (принимается для совместимости с init-скриптами). |
| `-v` | `--version` | Выводит версию движка (если указан до имени команды). |
| `-h` | `--help` | Выводит краткую справку (если указан до имени команды). |

### Объединение нескольких конфигурационных файлов

Если через `-c` и/или `-C` передано более одного файла, документы объединяются в порядке их следования:
- JSON-объекты объединяются рекурсивно по ключам;
- JSON-массивы конкатенируются (элементы последующих файлов добавляются в конец);
- при конфликте скалярных значений сохраняется значение из первого файла.

### `run`

Запускает движок с указанной конфигурацией. Перед открытием портов и интерфейсов выполняется полная валидация конфигурации; предупреждения о устаревших полях выводятся в `stderr` с префиксом `[WARN]`.

```bash
tachyon-core run -c /etc/tachyon-core/config.json -D /usr/share/tachyon-core
tachyon-core -D /etc/tachyon-core -C /etc/tachyon-core/conf.d run
```

Особенности запуска:
- На Linux и Android процесс при старте автоматически поднимает мягкий лимит открытых файловых дескрипторов (`RLIMIT_NOFILE`) до `min(rlim_max, 65535)`.
- Параметры рантайма Tokio (число рабочих потоков и пул блокирующих задач) автоматически рассчитываются по аппаратному профилю (доступные CPU, cgroup-квоты, доступная ОЗУ). При одном рабочем потоке (`workers == 1`) используется однопоточный планировщик `current_thread`, при `workers > 1` — `multi_thread`.
- На Unix-системах активна обработка `SIGHUP` (перезагрузка конфигурации), `SIGTERM` и `SIGINT` (корректное завершение).

### `check`

Проверяет один или несколько файлов конфигурации на синтаксис JSON, схему, ссылки между тегами, разворачивание блоков `subscription` и `fptn`.

```bash
tachyon-core check -c /etc/tachyon-core/config.json
tachyon-core check -C /etc/tachyon-core/conf.d
```

При успехе завершается с кодом `0` без вывода в `stdout`. При ошибке выводит диагностическое сообщение с указанием ожидаемого типа/значения по JSON-пути в `stderr` и завершается с кодом `1`.

### `reload-preview`

Сравнивает текущую и кандидатскую конфигурации и сообщает в JSON, возможна ли горячая перезагрузка без остановки входящих слушателей (`in_place: true`) или потребуется пересоздание слушателей (`in_place: false`).

```bash
tachyon-core reload-preview --current /etc/tachyon-core/config.json /tmp/config.new.json
tachyon-core reload-preview --current=/etc/tachyon-core/config.json -c /tmp/config.new.json
```

| Флаг / аргумент | Описание |
|---|---|
| `--current <file>`, `--current=<file>` | Обязательный путь к текущей активной конфигурации. |
| `<file>` или `-c`/`-C` | Кандидатская конфигурация (поддерживается один путь без флага либо стандартные `-c`/`-C`). |

Формат вывода (`stdout`):

```json
{
  "in_place": true,
  "current_digest": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
  "candidate_digest": "8f434346648f6b96df89dda901c5176b10a6d83961dd3c1ac88b59b2dc327aa4"
}
```

`current_digest` и `candidate_digest` — SHA-256 от сериализованного JSON всего документа (64 hex-символа).

Условия для `in_place: true`:
- Не изменились разделы `experimental.clash_api`, `experimental.cache_file`, `ntp` и (на Linux) `network_namespaces`.
- Не изменился состав и параметры `inbounds`, за двумя исключениями, которые поддерживаются на лету:
  1. добавление, изменение или удаление динамического слушателя с тегом `direct-proxy-in` (типы `mixed`, `socks`, `http`);
  2. изменение непустого списка `users` у инбаундов `vless`, `trojan`, `vmess`, `hysteria2`, `tuic`, `anytls`.

Изменения в `outbounds`, `endpoints`, `route`, `dns`, `log.level` и `log.disabled` применяются в режиме `in_place`.

### `format`

Форматирует JSON-файл конфигурации с отступами в 2 пробела.

```bash
tachyon-core format -c config.json
tachyon-core format -c config.json -w
```

| Флаг | Описание |
|---|---|
| `-c <path>`, `--config <path>` | Исходный файл конфигурации (обязательный). |
| `-w`, `--write` | Перезаписать исходный файл на месте (с завершающим переносом строки). Без флага результат выводится в `stdout`. |

### `merge`

Объединяет несколько JSON-файлов конфигурации по правилам рекурсивного слияния и записывает результат в выходной файл.

```bash
tachyon-core merge /tmp/merged.json -c base.json -c outbounds.json -c route.json
```

| Аргумент / флаг | Описание |
|---|---|
| `<output-path>` | Путь к результирующему файлу (первый позиционный аргумент). |
| `-c <path>`, `--config <path>` | Входной файл конфигурации (указывается один или более раз). |

После записи выводит путь к выходному файлу и отформатированный JSON в `stdout`.

### `generate`

Генерирует ключевые пары, самоподписанные сертификаты, UUID и случайные байты с использованием криптографического ГСЧ ОС (`OsRng`).

```bash
tachyon-core generate <подкоманда> [параметры]
```

| Подкоманда | Аргументы / флаги | Формат вывода |
|---|---|---|
| `reality-keypair` | — | Пара ключей X25519 в URL-safe Base64 без padding (`PrivateKey:` и `PublicKey:`). |
| `tls-keypair` | `[server_name]` (по умолчанию `localhost`), `-m`/`--months <N>` (по умолчанию `12`) | Приватный ключ и самоподписанный сертификат X.509 в формате PEM. |
| `wg-keypair` | — | Пара ключей Curve25519 (с clamping) для WireGuard/AmneziaWG в стандартном Base64 (`PrivateKey:` и `PublicKey:`). |
| `uuid` | — | Случайный UUID версии 4 (RFC 4122). |
| `rand` | `[--base64\|--hex]` (по умолчанию `--base64`), `[<len>]` (по умолчанию `16` байт) | Случайная последовательность байт в Base64 или hex (например, для `short_id` REALITY или паролей Shadowsocks-2022). |

Примеры:

```bash
tachyon-core generate reality-keypair
tachyon-core generate tls-keypair example.com --months 24
tachyon-core generate wg-keypair
tachyon-core generate uuid
tachyon-core generate rand --hex 8
tachyon-core generate rand --base64 32
```

### `rule-set`

Инструменты для работы с наборами правил в текстовом (`.json`), двоичном sing-box (`.srs`) и zero-copy mmap-формате `tachyon-core` (`.trs` / TSRS). Подробнее о форматах см. [Форматы наборов правил](../03-protocols-and-formats/ruleset-formats.md).

Во всех подкомандах вместо пути к файлу можно передать `-` или `stdin` для чтения из стандартного ввода.

| Подкоманда | Синтаксис | Описание |
|---|---|---|
| `compile` | `rule-set compile [флаги] <source-path>` | Компилирует JSON (или перекодирует `.srs`) в `.srs` либо `.trs`. |
| `decompile` | `rule-set decompile [флаги] <binary-path>` | Декомпилирует `.srs` или `.trs` в отформатированный JSON (одноэлементные списки сворачиваются в скаляры). |
| `match` | `rule-set match [флаги] <rule-set-path> [target]` | Проверяет совпадение домена или IP-адреса с правилами в JSON, `.srs` или `.trs`. |
| `format` | `rule-set format <rule-set-path>` | Читает JSON или `.srs` и выводит нормализованный JSON в `stdout`. |
| `upgrade` | `rule-set upgrade <rule-set-path>` | Повышает версию схемы набора правил до актуальной (`3`) и выводит JSON в `stdout`. |

Флаги подкоманд `rule-set`:

| Флаг | Подкоманды | Описание |
|---|---|---|
| `-o <path>`, `--output <path>` | `compile`, `decompile` | Путь к выходному файлу. По умолчанию для `compile` заменяет `.json`/`.srs` на `.srs` (или `.trs`), для `decompile` заменяет `.srs`/`.trs`/`.tsr` на `.json`. |
| `-f <fmt>`, `--format <fmt>` | `compile` | Целевой формат компиляции: `trs` / `tsr` (zero-copy `mmap`) или `srs` (по умолчанию). Формат `.trs` также выбирается автоматически, если `-o` оканчивается на `.trs` или `.tsr`. |
| `-d <domain>`, `--domain <domain>` | `match` | Проверяемое доменное имя (сравнение без учёта регистра). |
| `-i <ip>`, `--ip <ip>` | `match` | Проверяемый IPv4- или IPv6-адрес. |

Примеры:

```bash
# Компиляция в zero-copy .trs из .json или существующего .srs
tachyon-core rule-set compile -f trs -o /tmp/geo.trs rules.json
tachyon-core rule-set compile -o /tmp/geo.trs geosite.srs

# Компиляция в стандартный .srs
tachyon-core rule-set compile -o rules.srs rules.json

# Декомпиляция .trs или .srs обратно в JSON
tachyon-core rule-set decompile -o rules.json /tmp/geo.trs

# Проверка домена или IP (аргумент может быть позиционным или через -d / -i)
tachyon-core rule-set match /tmp/geo.trs example.com
tachyon-core rule-set match --ip 192.168.1.10 rules.srs
```

Для `.trs`-файлов `rule-set match` открывает файл через zero-copy `mmap` и выводит `[0] match` либо `no match`. Для JSON и `.srs` выводятся индексы всех сработавших правил (`[0] match`, `[3] match`, ...).

### `api`

Минимальный синхронный HTTP/1.1-клиент для обращения к локальному контроллеру Clash/Tachyon API без зависимости от `curl`.

```bash
tachyon-core api [--url <URL>] [--secret <SECRET>] <method> <path> [body]
tachyon-core api [--url <URL>] [--secret <SECRET>] <path>
```

| Параметр / флаг | Переменная окружения | Описание |
|---|---|---|
| `--url <URL>`, `--url=<URL>` | `BOX_API_URL` | Базовый адрес контроллера (например, `http://127.0.0.1:9090` или `127.0.0.1:9090`). Поддерживается только незашифрованный HTTP (`https://` отклоняется). |
| `--secret <SECRET>`, `--secret=<SECRET>` | `BOX_API_SECRET` | Секрет авторизации; передаётся в заголовке `Authorization: Bearer <secret>`. |
| `<method>` | — | HTTP-метод (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`). Если передан только один позиционный аргумент, используется `GET`. |
| `<path>` | — | Путь запроса с опциональными query-параметрами (например, `/proxies`, `/tachyon/health`). |
| `[body]` | — | Необязательное тело запроса; при наличии автоматически добавляется `Content-Type: application/json`. |

При статусе `2xx` тело ответа печатается в `stdout` (код возврата `0`), при любом другом статусе ошибка печатается в `stderr` (код возврата `1`).

```bash
export BOX_API_URL=http://127.0.0.1:9090
export BOX_API_SECRET=mysecret
tachyon-core api /version
tachyon-core api PUT /proxies/proxy '{"name":"node-de-1"}'
tachyon-core api POST /tachyon/route-check '{"target":"https://example.com"}'
```

### `subscription` (псевдоним `sub`)

Загрузка подписок с адаптивным подбором `User-Agent`, разбор поддерживаемых форматов (URI-списки, Base64, Xray JSON, sing-box JSON, Clash YAML, SIP008, FPTN), расшифровка защищённых ссылок и инспекция HWID устройства.

#### `subscription fetch`

```bash
tachyon-core subscription fetch <url> [флаги]
```

| Флаг | Описание |
|---|---|
| `--ua <ua>`, `--user-agent <ua>` | Принудительный заголовок `User-Agent` (отключает автоматический перебор профилей). |
| `--hwid [id]`, `--hwid=<id\|true\|false>` | Включить отправку HWID-заголовков (включено по умолчанию) или задать явный идентификатор. |
| `--no-hwid` | Отключить отправку HWID-заголовков. |
| `-k`, `--insecure` | Пропустить проверку TLS-сертификата сервера подписки. |
| `-x <url>`, `--proxy <url>` | Выполнить HTTP-запрос через указанный прокси (например, `socks5://127.0.0.1:2080`). |
| `-H "Key: Value"`, `--header "Key: Value"` | Добавить произвольный HTTP-заголовок (можно повторять). |
| `-f <fmt>`, `--format <fmt>` | Формат вывода: `outbounds` (по умолчанию — JSON-массив аутбаундов), `links` (URI по строкам), `raw` (исходное тело ответа), `full` / `json` (полный объект с `user_agent`, `user_info`, `metadata`, `primary_tags`, `raw_body`, `outbounds`). |
| `-o <file>`, `--output <file>` | Записать результат в файл вместо `stdout`. |

#### `subscription parse`

Разбирает подписку из файла, `stdin` (`-`) или непосредственно переданного URI.

```bash
tachyon-core subscription parse [<file>|-|<uri>] [флаги]
```

| Флаг | Описание |
|---|---|
| `-c <file>`, `--config <file>` | Альтернативный способ указать входной файл. |
| `--headers <file>` | Файл с сохранёнными HTTP-заголовками ответа (по одной паре `Key: Value` на строку; используется в том числе для синтеза WireGuard-профилей из заголовков). |
| `-H "Key: Value"`, `--header "Key: Value"` | Передать отдельный HTTP-заголовок ответа. |
| `--hwid <id>` | Явный HWID для расшифровки содержимого. |
| `-f <fmt>`, `--format <fmt>` | Формат вывода: `outbounds` (по умолчанию), `links`, `full` / `json`, `raw` / `url` (выводит только расшифрованное/развёрнутое содержимое). |
| `-o <file>`, `--output <file>` | Записать результат в файл вместо `stdout`. |

#### `subscription decrypt`

Расшифровывает зашифрованную ссылку или тело ответа подписки и выводит результат в `stdout`.

```bash
tachyon-core subscription decrypt [<link>|<file>|-] [--hwid <id>] [--url <source-url>] [--tag <encrypt-tag>]
```

| Флаг | Описание |
|---|---|
| `--hwid <id>` | Кандидат ключа HWID для расшифровки. |
| `--url <url>` | Исходный URL подписки (используется для расшифровки тела ответа). |
| `--tag <tag>`, `--encrypt-tag <tag>` | Тег шифрования из заголовков ответа сервера подписки. |

#### `subscription hwid`

Выводит JSON-объект с автоматически определёнными заголовками идентификации устройства:

```bash
tachyon-core subscription hwid
```

```json
{
  "X-HWID": "a1b2-c3d4-e5f6-7890",
  "X-Device-OS": "OpenWrt",
  "X-Ver-OS": "24.10.0",
  "X-Device-Model": "Xiaomi Mi Router AX3000T"
}
```

### `fptn`

Декодирует токен доступа `fptn:` (Base64) или `fptnb:` (Brotli + Base64) в структурированный JSON.

```bash
tachyon-core fptn decode "fptn:..."
```

### `netns-holder`

Служебная команда (доступна только на Linux). Вызывается движком при использовании секции `network_namespaces` с типом `unshare`: удерживает открытым созданный сетевой namespace до закрытия `stdin`. Не предназначена для прямого ручного запуска.

## Коды возврата

| Код | Значение |
|---|---|
| `0` | Успешное выполнение команды или корректное завершение `run` по `SIGTERM` / `SIGINT`. |
| `1` | Ошибка аргументов CLI, невозможность сменить каталог (`-D`), ошибка валидации конфигурации (`check`/`run`), ошибка запуска слушателей, неуспешный откат после критического сбоя перезагрузки, либо HTTP-статус не `2xx` в команде `api`. |

## Переменные окружения

Движок автоматически адаптирует размеры буферов, окон и пулов под аппаратный профиль системы (см. [Адаптация к памяти и оборудованию](../01-architecture/memory-and-hardware.md)). При необходимости параметры переопределяются следующими переменными окружения:

### Рантайм, память и планировщик

| Переменная | Допустимые значения | По умолчанию | Назначение |
|---|---|---|---|

## Обработка сигналов ОС

На Unix-платформах (Linux, OpenWrt, macOS) команда `run` устанавливает обработчики сигналов:

| Сигнал | Поведение |
|---|---|
| `SIGHUP` | Горячая перезагрузка конфигурации без остановки процесса. |
| `SIGTERM` | Корректное завершение работы (`graceful shutdown`). |
| `SIGINT` | Корректное завершение работы (аналогично `SIGTERM` и `Ctrl+C` на Windows). |

### Алгоритм перезагрузки по `SIGHUP`

1. Движок повторно читает конфигурацию из тех же путей `-c`/`-C`, с которыми был запущен.
2. Выполняется полная проверка схемы (`check_str`). При ошибке чтения, разбора или валидации текущая работающая конфигурация не затрагивается, ошибка пишется в лог.
3. Проверяется возможность обновления на месте (`can_reload_in_place`):
   - **Обновление без простоя (`in_place`)**: заранее собираются и валидируются новый маршрутизатор, DNS-сервис, эндпоинты и удалённые наборы правил; при успехе состояние атомарно подменяется, активные TCP/UDP-соединения не обрываются, кэши DNS и FakeIP мигрируют в новый экземпляр.
   - **Перезапуск слушателей (cold reload)**: если изменились `inbounds`, `clash_api`, `cache_file`, `ntp` или `network_namespaces`, выполняется полное ожидание освобождения всех TCP/UDP/QUIC-сокетов (`shutdown_wait`), затем запускается новая конфигурация. При ошибке старта новой конфигурации движок автоматически откатывается к предыдущей рабочей конфигурации. Если не удалось поднять ни новую, ни прежнюю конфигурацию, процесс завершается с кодом `1`, чтобы сервис-менеджер (`procd`/`systemd`) перезапустил службу.

### Алгоритм корректного завершения (`SIGTERM` / `SIGINT`)

1. Отменяются фоновые задачи слушателей, зондов и эндпоинтов; QUIC-эндпоинтам отправляется кадр закрытия.
2. Сбрасываются на диск накопленные счётчики устройств и грязные бакеты `cache.db`, освобождается lock-файл кэша.
3. Движок дожидается фактического закрытия всех UDP- и QUIC-сокетов (с периодическими предупреждениями watchdog каждые 20 с, если какой-либо сокет удерживается).
4. Рантайм Tokio завершается с таймаутом 250 мс для блокирующих потоков, чтобы процесс не задерживал перезапуск службы.

## Логирование

> **Важно:** переменная окружения `RUST_LOG` в `tachyon-core` **не используется** и никак не влияет на вывод. В движке не применяется фильтрация логов через `env_logger` или `tracing_subscriber`.

Все параметры логирования задаются исключительно в секции `log` JSON-конфигурации (см. [Обзор схемы конфигурации](../02-config/schema-overview.md)):

```json
{
  "log": {
    "disabled": false,
    "level": "info",
    "output": "/tmp/tachyon-core/tachyon-core.log",
    "timestamp": true
  }
}
```

| Поле `log` | Значения | По умолчанию | Описание |
|---|---|---|---|
| `disabled` | `true` / `false` | `false` | Полностью отключает запись логов (уровень можно включить повторно через `PATCH /configs` или перезагрузку). |
| `level` | `trace`, `debug`, `info`, `warn` (или `warning`), `error` (или `fatal`) | `info` | Минимальный уровень важности записываемых сообщений. |
| `output` | `""`, `stderr`, `stdout` или путь к файлу | `stderr` | Назначение вывода. При указании пути к файлу консольный вывод отключается. На роутерах OpenWrt стандартный путь — `/tmp/tachyon-core/tachyon-core.log` (в `tmpfs`). |
| `timestamp` | `true` / `false` | `false` | Добавляет локальную метку времени `YYYY-MM-DD HH:MM:SS` перед уровнем сообщения. |

Особенности подсистемы логирования:
- **Защита от переполнения диска/tmpfs**: при записи в файл ведётся учёт размера; при превышении `2 MiB` файл автоматически усекается до `0` байт и запись продолжается с начала.
- **Кольцевой буфер в памяти**: последние `1024` записи хранятся в памяти и доступны через потоковый эндпоинт `GET /logs` (HTTP chunked / WebSocket) и через `GET /tachyon/logs/recent`.
- **Изменение уровня без перезапуска**: уровень `log.level` можно изменить на лету через `PATCH /configs` (включая временное повышение уровня с автоматическим откатом по `ttl_sec` от 5 до 300 секунд) либо через `SIGHUP` / `PUT /configs`. Смена `log.output` требует перезапуска процесса.
