# Нативная десинхронизация (`desync`)

Аутбаунд `"type": "desync"` — встроенный в `tachyon-core` механизм пакетной десинхронизации TCP и UDP для прямых исходящих соединений. В отличие от прокси-серверов и туннелей, `desync` отправляет трафик напрямую целевому узлу, модифицируя только начальный обмен (TCP/TLS/HTTP-рукопожатие и стартовые UDP/QUIC-дейтаграммы) для устранения помех со стороны промежуточных сетевых узлов (middlebox). После завершения начального обмена поток передаётся напрямую с минимальными накладными расходами и без промежуточного ретранслятора.

Общие поля подключения (`dialer`, например `bind_interface`, `routing_mark`, `domain_resolver`, `domain_strategy`, `connect_timeout`, `fallback_delay`) поддерживаются полностью и описаны в [Общих объектах конфигурации](../common-objects.md).

## Полная таблица полей

### Базовые поля, пресеты и адаптивный режим

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `type` | `string` | — | Обязательно: `"desync"`. |
| `tag` | `string` | `""` | Уникальный тег аутбаунда. |
| `preset` | `string` | `"fake_split"` | Именованный набор стартовых параметров (см. раздел «Пресеты и режимы» ниже). |
| `mode` | `string` | Из `preset` (`"fake_split"`) | Явный режим TCP-десинхронизации. Переопределяет режим, заданный в `preset`. Значения `"auto"`, `"adaptive"`, `"smart"` включают `auto_tune: true`; `"none"` / `"off"` / `"disabled"` отключают десинхронизацию. |
| `auto_tune` | `boolean` | Зависит от цели (см. ниже) | Управляет адаптивным подбором стратегий и горячим повтором при отказах. Явное `"auto_tune": false` полностью фиксирует ручные параметры. |

### Параметры TCP-сегментации и служебных пакетов

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `fooling` | `string` | `"md5"` | Способ отбраковки служебного TCP-пакета целевым сервером (см. таблицу методов `fooling` ниже). |
| `split_pos` | `integer` \| `string` \| `array` | `"midsld"` | Позиция (или список позиций) разбиения первого TCP-сегмента: положительное смещение в байтах, символьный маркер (см. таблицу ниже), массив позиций или строка через запятую (например, `"1,midsld"`). |
| `tlsrec_first` | `boolean` | `false` | Предварительно разбивает первую запись TLS ClientHello на уровне протокола TLS (RFC-совместимая фрагментация TLS-записей) до применения TCP-сегментации. |
| `seqovl` | `integer` | `0` | Длина перекрытия порядковых номеров TCP (sequence overlap) в байтах (`0..=256`; `0` — отключено). |
| `syndata` | `boolean` | `false` | Включает передачу начальной служебной полезной нагрузки в процессе установления TCP-соединения (`SYN`). |

| `wsize` | `integer` | `0` | Ограничение начального окна приёма TCP (`0..=65535` байт; `0` — не изменять) для стимуляции сегментации `ServerHello` со стороны сервера. |
| `wscale` | `integer` | `null` | Коэффициент масштабирования окна приёма TCP (`0..=14`), применяемый совместно с `wsize`. |
| `scale` | `integer` | `null` | Алиас поля `wscale` (`0..=14`). |
| `ipfrag` | `boolean` | `false` | Включает фрагментацию на уровне IP-пакетов. |
| `fake_ttl` | `integer` | `6` | Значение IP TTL / Hop Limit для служебных TCP-пакетов (`1..=128`). |
| `fake_sni` | `string` | `"www.google.com"` | Непустое доменное имя SNI, подставляемое при формировании служебного TLS ClientHello. |
| `sni_pool` | `string[]` | — | Список доменных имён для SNI. Если `fake_sni` не задан явно, первый непустой элемент массива используется как `fake_sni`. |
| `fake_payload` | `string` | — | Пользовательское содержимое служебного TCP-пакета: hex-строка чётной длины с префиксом `0x` / `0X` либо обычная текстовая строка. |
| `fake_tls` | `string` | — | Алиас поля `fake_payload`. |
| `repeats` | `integer` | `1` | Количество повторов служебного TCP-пакета (`1..=100`). |
| `split_delay_ms` | `integer` | `1` | Пауза в миллисекундах между отправкой сегментов (`0..=1000`). |

| `fake_disorder` | `fakedisorder`, `fakeddisorder`, `faked_disorder`, `fake,disorder`, `fake,disorder2`, `fake+disorder` | `mode: "fake_disorder"`, `split_pos: "midsld"`, `fake_ttl: 6`, `udp_fake: true`. |

| `multi_split` | `multisplit`, `multisplit2`, `fake,multisplit` | `mode: "multi_split"`, `split_pos: "midsld"`, `udp_fake: false`. |
| `split` | `split2` | `mode: "split"`, `split_pos: "midsld"`, `udp_fake: false`. |
| `disorder` | `disorder2` | `mode: "disorder"`, `split_pos: 1`, `udp_fake: false`. |
| `tlsrec` | `tls_rec` | `mode: "tlsrec"`, `split_pos: "sni"`, `udp_fake: false`. |
| `fake` | `syndata` | `mode: "fake"`, `fake_ttl: 6`, `udp_fake: true`. |
| `oob` | — | `mode: "oob"`, `split_pos: 1`, `udp_fake: false`. |

Явно заданные в объекте аутбаунда поля (`mode`, `split_pos`, `fooling`, `udp_fake`, `auto_tune` и т. д.) всегда имеют приоритет над значениями из `preset`.

### Режимы TCP (`mode`)

| Режим | Описание |
|---|---|
| `fake_split` | Отправка служебного пакета (с методом отбраковки `fooling`) совместно с разбиением исходного TCP-сегмента в точке `split_pos`. |
| `fake_disorder` | Служебный пакет + разбиение с отправкой сегментов в обратном порядке (disorder). |
| `multi_split` | Разбиение первого TCP-сегмента на несколько частей (по списку позиций `split_pos` или многоточечному профилю). |
| `multi_disorder` | Многоточечное разбиение с изменением порядка доставки сегментов и служебным пакетом. |
| `split` | Чистое разбиение первого TCP-сегмента без служебных пакетов. |
| `disorder` | Разбиение с изменением порядка сегментов без служебных пакетов. |
| `tlsrec` | Фрагментация записи TLS ClientHello на уровне протокола TLS (не требует привилегий raw-сокетов). |
| `fake` | Отправка служебного пакета без разбиения исходного сегмента. |
| `oob` | Вставка внеполосного (Out-Of-Band / urgent) байта в TCP-сегмент в позиции `split_pos`. |
| `disoob` | Комбинация изменения порядка сегментов (disorder) и внеполосного (OOB) байта. |
| `none` *(алиасы `off`, `disabled`)* | Отключает десинхронизацию; трафик идёт как обычное прямое соединение. |

Кроме того, в поле `mode` принимаются адаптивные алиасы `"auto"`, `"adaptive"`, `"smart"` (активируют `auto_tune: true` и базовый режим `fake_split`) и `"hostfakesplit"` / `"host_fake_split"` (активируют `fake_split` + `host_fake: true`).

### Маркеры позиции разбиения (`split_pos`)

| Значение | Алиасы | Точка разбиения |
|---|---|---|
| Положительное целое `N` | `"N"` | Смещение ровно на `N` байт от начала полезной нагрузки (например, `1`, `2`). |
| `"sni"` | `"sniext"` | Начало поля имени хоста в расширении TLS SNI (или заголовка HTTP `Host`). |
| `"sniext+1"` | `"sni+1"` | 1 байт после начала расширения SNI. |
| `"host+1"` | — | 1 байт после начала имени хоста. |
| `"midsld-2"` | `"sld-2"` | 2 байта до середины домена второго уровня (SLD). |
| `"midsld"` | `"sld"`, `"host"` | Середина домена второго уровня (SLD) внутри SNI / HTTP `Host` (по умолчанию). |
| `"midsld+2"` | `"sld+2"` | 2 байта после середины SLD. |
| `"endhost-1"` | `"endsld-1"`, `"endhost"` | 1 байт до конца имени хоста. |
| `"extlen"` | — | Поле длины расширений TLS ClientHello. |

### Методы отбраковки служебного пакета (`fooling`)

| Метод | Алиасы | Механизм отбраковки целевым сервером |
|---|---|---|
| `md5` *(по умолчанию)* | `md5sig`, `tcp_md5`, `tcp_md5sig`, `wrong-md5`, `wrong_md5` | TCP Option 19 (MD5 Signature) — детерминированно отбрасывается сетевым стеком целевого сервера независимо от числа сетевых переходов. |
| `timestamp` | `ts`, `tcp_ts`, `wrong-timestamp`, `wrong_timestamp` | Устаревшая метка времени TCP Timestamp (отбрасывается механизмом PAWS, RFC 7323). |
| `badseq` | `seq`, `wrong-sequence`, `wrong_sequence` | Порядковый номер TCP вне актуального окна. |
| `badack` | `ack`, `tcp_ack`, `wrong-ack`, `wrong_ack` | Номер подтверждения ACK вне окна приёма. |
| `badsum` | `sum`, `wrong-checksum`, `wrong_checksum` | Некорректная контрольная сумма TCP. |
| `autottl` | `auto_ttl`, `ttl`, `low-ttl`, `low_ttl` | Ограниченный IP TTL / Hop Limit (`fake_ttl`), истекающий на пути до целевого сервера. |
| `hopbyhop` | `ip6_hopbyhop`, `hopbyhop2`, `ip6_hopbyhop2`, `destopt`, `ip6_destopt` | Заголовки расширений IPv6 (на IPv4 автоматически переходит в совместимый комбинированный вариант). |
| `badseq_badack_badsum` | `combo`, `badsum_combo`, `badseq,badsum` | Комбинированная отбраковка по `seq`, `ack` и контрольной сумме. |
| `md5_badack` | `tcp_md5_badack`, `md5+badack`, `md5sig_badack`, `md5sig+badack`, `md5sig,badack` | Комбинация TCP MD5 и смещённого `ack` с валидной контрольной суммой L4. |
| `datanoack` | `data_no_ack`, `noack` | Сброшенный флаг `ACK` в сегменте данных в сочетании с TCP MD5 (отбрасывается согласно RFC 793). |

## Поведение `auto_tune` и архитектура адаптивного режима

### Соотношение ручного и адаптивного режимов

- **Адаптивный режим (`preset: "auto"` / `mode: "adaptive"` / `auto_tune: true`, а также при неуказанном `auto_tune` для внешних не-loopback адресов):** движок использует собственный набор комбинированных стратегий TCP и UDP, автоматически выбирая оптимальный вариант для каждого хоста, выполняя горячие повторные попытки при сбое рукопожатия и обучаясь на результатах реальных соединений.
- **Строгий ручной режим (`"auto_tune": false`):** адаптивный подбор и автоматический перебор стратегий отключены; для каждого соединения применяются исключительно заданные в конфигурации `mode`, `split_pos`, `fooling`, `tlsrec_first`, `seqovl`, `wsize`/`wscale`, `udp_*` и `quic_*`.

### Многоуровневая адаптивная память

В адаптивном режиме движок поддерживает трёхуровневую иерархию памяти стратегий, чтобы сокращать число пробных соединений при обращении к новым ресурсам:

1. **Уровень точного хоста** — хранит подтверждённую рабочую стратегию для конкретного домена (SNI / Host) или целевого адреса.
2. **Уровень родительского домена и подсети** — обобщает успешный опыт на родственные поддомены (`eTLD+1`) и узлы в той же подсети, позволяя применять подходящую стратегию с первой попытки.
3. **Глобальный рейтинг провайдера** — ведёт общую статистику эффективности стратегий в текущей сети и задаёт порядок кандидатов для ранее не встречавшихся ресурсов.

Аналогичный учёт ведётся для UDP/QUIC-потоков и доступности IPv4/IPv6-кандидатов: при недоступности предпочтительного семейства адресов (например, при неработающем маршруте IPv6) движок временно понижает проблемный адрес и перенаправляет последующие соединения по рабочему семейству.

### Контроль деградации после рукопожатия

Стратегия считается надёжно подтверждённой не только по факту получения ответа на рукопожатие, но и по устойчивой передаче полезной нагрузки:

- Отслеживаются отказы установки соединения, таймауты, сбросы TCP (`RST`), ранние обрывы потока и устойчивое ограничение пропускной способности на начальном участке передачи.
- Единичный случайный разрыв на длительном неактивном соединении не приводит к немедленному исключению рабочей стратегии; для понижения или исключения варианта учитываются повторяющиеся признаки деградации в ограниченном временном окне.
- При смене параметров конфигурации `desync` (при перезапуске или горячей перезагрузке) отпечаток конфигурации меняется, и устаревшие выученные записи автоматически перепроверяются.

### Персистентность в `cache.db` и бережное отношение к flash

При включённом `experimental.cache_file` (см. [Экспериментальные параметры](../experimental.md)) выученные профили `desync` сохраняются между перезапусками ядра:

- Данные адаптивной памяти размещаются в отдельной волатильной области кэша (не перезаписывая основную базу при каждом обновлении записи).
- Запись на накопитель буферизуется и выполняется отложенными пакетами согласно параметрам `experimental.cache_file.buffer_size` и `experimental.cache_file.flush_interval` (а также при корректном завершении работы).
- Такой подход минимизирует количество циклов стирания/записи на встроенной NAND/NOR flash-памяти роутеров OpenWrt при постоянной работе.

## Готовые примеры конфигураций

### 1. Рекомендуемый адаптивный профиль (универсальный)

Подходит для большинства домашних роутеров и рабочих станций: автоматический подбор стратегий для TCP и UDP/QUIC с сохранением обученного состояния в `cache.db`.

```json
{
  "type": "desync",
  "tag": "desync-auto",
  "preset": "auto",
  "auto_tune": true,
  "udp_fake": true,
  "quic_desync": true,
  "connect_timeout": "5s"
}
```

### 2. Ручной профиль без адаптивного подбора (TCP + TLS Record Split + Window Clamp)

Фиксированная конфигурация с отключённым `auto_tune`, предварительной фрагментацией TLS-записи, разбиением в двух точках, методом `md5_badack`, пользовательским пулом SNI и ограничением окна приёма `wsize`/`wscale`.

```json
{
  "type": "desync",
  "tag": "desync-manual-tcp",
  "mode": "fake_split",
  "auto_tune": false,
  "tlsrec_first": true,
  "split_pos": [1, "midsld"],
  "fooling": "md5_badack",
  "host_fake": true,
  "seqovl": 32,
  "wsize": 4096,
  "wscale": 4,
  "sni_pool": ["www.example.com", "cdn.example.net"],
  "repeats": 2,
  "split_delay_ms": 1,
  "udp_fake": false,
  "quic_desync": false
}
```

### 3. Профиль для UDP-потоков с явной служебной полезной нагрузкой и диапазоном пакетов

Фиксированный ручной профиль для специализированных UDP-приложений (например, голосовых или игровых потоков) с явным hex-шаблоном `udp_fake_payload`, диапазоном `udp_out_range` и сохранением локального сокета.

```json
{
  "type": "desync",
  "tag": "desync-udp-custom",
  "mode": "fake",
  "auto_tune": false,
  "udp_fake": true,
  "udp_repeats": 6,
  "udp_fake_ttl": 6,
  "udplen": 20,
  "udp_fake_payload": "0x000100002112a442b7e7a701bc34d686fa87dfae",
  "udp_out_range": "1-2",
  "udp_keep_socket": true,
  "quic_desync": true,
  "quic_repeats": 4
}
```

### 4. Беспривилегированный профиль (только фрагментация TLS-записей)

Не использует raw-сокеты и работает без `CAP_NET_RAW` / прав root: выполняет только RFC-совместимое разбиение TLS-записи ClientHello в области SNI.

```json
{
  "type": "desync",
```
