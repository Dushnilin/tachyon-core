# Размер бинаря, сжатие и «light»-сборка

Замеры сделаны 2026-09-30 на текущем `main` (`6598455`), релизный профиль
уже настроен на минимум:

```toml
[profile.release]
opt-level = "z"      # минимая оптимизация по размеру
lto = true
codegen-units = 1
panic = "abort"      # без таблиц раскрутки стека
strip = "symbols"    # без отладочных символов
```

То есть «дешёвые» рычаги уже выжаты: `panic = "abort"` в этом проекте ничего
не даёт (проверено отдельной пересборкой с `-Cpanic=abort` — те же
5 489 664 байта), `opt-level = "z"`, LTO и strip уже включены.

## 1. Сколько весит сейчас

| что | байт | МБ |
|---|---|---|
| `tachyon-core` (windows-amd64, релиз) | 5 489 664 | 5,24 МиБ |
| эталон `sing-box 1.14.2-lx.8` (windows-amd64) | 69 004 288 | 65,8 МиБ |
| `libcronet.dll` рядом с эталоном | 9 529 344 | 9,09 МиБ |

Мы уже в **12,6 раза** меньше эталона, и это до того, как сделана часть
роадмапа. Причина — чистый Rust: в нас 220 крейтов, из них ни одного C-крипто
(нет `ring`, `aws-lc`, `boring`, `openssl`), а у эталона рядом лежит отдельная
`libcronet.dll` на 9 МБ.

## 2. Сжатие — сколько реально выигрываем

Все цифры — на текущем бинаре (5 489 664 Б):

| способ | байт | доля |
|---|---|---|
| как есть | 5 489 664 | 100% |
| `gzip -9` | 2 540 471 | 46% |
| `brotli -q 11` | 2 005 755 | 36% |
| **`xz -9e`** | **1 982 760** | **36%** |
| `upx -9` | 2 094 592 | 38% |

Выводы:

* **Упаковывать надо xz-ом (или brotli), и это делается в пакете.** −64% от
  размера, ноль изменений в коде.
* **UPX не нужен.** 2,09 МБ против 1,98 МБ у xz — выигрыша ноль, а минусы
  реальные: распаковка при каждом старте (на роутере с флешем это заметно),
  антивирусы и сигнатуры срабатывают регулярно, отладка символами
  невозможна. Не делаем.
* Для сравнения, эталон после тех же операций: `xz` → 17,47 МБ, `upx` →
  21,32 МБ. То есть даже в упакованном виде мы меньше эталона в 8,8 раза.
* Важно различать **скачанный** и **установленный** размер: xz уменьшает только
  первый. На роутере с 16 МБ флеша решает именно установленный размер.

## 3. Сколько будет весить, когда всё допишем

Оценка по зависимостям, которые добавит каждый пункт роадмапа (чистый Rust,
релизный профиль выше, `opt-level = "z"` + LTO):

| пункт роадмапа | прирост | комментарий |
|---|---|---|
| uTLS / REALITY | +1,5…2,5 МБ | форк rustls с базой отпечатков; самый дорогой пункт |
| F5: серверные инбаунды | +0,3…0,6 МБ | переиспользуем уже написанные ядра протоколов |
| F6: `tun` + netlink | +0,3…0,5 МБ | заодно заменим polling `/proc` на rtnetlink |
| `ssh`-аутбаунд (russh) | +1,5…2 МБ | полноценный SSH-клиент |
| `tor` | ~0 | спавнит системный бинарь `tor` и говорит с ним по SOCKS5 |
| `cloudflared` | +0,1 МБ | h2 уже в бинаре |
| `hysteria` v1 | +0,1 МБ | quic уже в бинаре |
| `bridge` | +0,05 МБ | только ioctl/netlink |
| `tailscale` | +5…10 МБ | фактически переписать tailscaled: noise, DERP, netmap, wireguard |
| `openconnect` | +2…4 МБ | свой SSL-VPN клиент |

Итого:

* **Полный паритет без tailscale/openconnect: ~9…11 МБ.**
* **С ними: ~16…21 МБ.**

Это важно, потому что в `.github/workflows/ci.yml` уже стоит бюджет
**≤ 12 МиБ** на musl-сборках. Полный роадмап в него не влезает, и первыми из
бюджета вылетят как раз uTLS и tailscale. Это не повод бросать работу, но
бюджет придётся поднимать осознанно, вместе с решением по tailscale.

## 4. Можно ли сделать «light» без лишнего функционала

**Честный ответ: отдельная light-сборка сегодня не окупается, но один
осмысленный переключатель есть.**

Почему не окупается: протоколы у нас не сидят за cargo-фичами, и не потому что
лень, а потому что `check` (валидатор конфигов) и дифференциальный корпус
ссылаются на каждый протокод сразу. Чтобы сделать light, пришлось бы гонять
вейт по матрице фич — гейт дорожает в разы, а выигрыш в бинаре дают
десятки протоколов, а не один-два.

Что реально весит (это и есть будущие оси, если понадобится):

| ось | выигрыш | кому нужно |
|---|---|---|
| без QUIC (убираем quinn + h3 + smoltcp) | −1,5…2 МБ | кому никогда не нужен tuic/hysteria/wireguard-аутбаунд |
| без brotli | −0,3 МБ | кому не нужны `.br`-rule-set'ы |
| без `clash_api` | −0,1 МБ | почти никому, смысла нет |
| без `regex` | невозможно | регулярки нужны доменным правилам и rule-set'ам |

Вывод: **одна осмысленная ось — `quic`**, и то по запросу. Держать двадцать
переключателей «по протоколу» — это ровно тот оверинжиниринг, которого мы
избегаем.

Что сделать вместо «light»:

1. **Упаковать xz-ом в пакете** — 5,2 МБ → 2,0 МБ, одна строка в пайплайне.
2. **Оставить один бинарь**, а не два: 5,2 МБ на роутере — уже впритык, но
   для 99% конфигураций (yaml-конфиг, роутер-прошивка) это перебор «лишнего».
3. Если флеш 8…16 МБ — тогда да, имеет смысл ровно один `quic`-feature.
   Сделаем, когда будет первый реальный запрос, и закроем его одним
   дополнительным билдом в CI, а не матрицей.

## 5. Что предлагаю сделать сейчас

Ничего. Конкретно:

* `panic = "abort"`, `strip`, `opt-level = "z"` — уже включены, повторно
  трогать нечего.
* UPX не внедряем.
* xz в пакете — добавим, когда появится сам пакет (сейчас в `tachyon-core`
  только CI-артефакты, сборщика пакета здесь нет).
* Бюджет 12 МиБ в CI пока не трогаем: до uTLS/tailscale есть запас, а решение
  принимаем вместе с ними.

Отдельно: локальный `target/` уже 98 ГБ — его стоит почистить, но на размер
бинаря это не влияет.
