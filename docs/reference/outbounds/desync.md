# Аутбаунд `desync`

Исходящее прямое соединение с адаптивной сегментацией TCP-потоков и предварительной отправкой UDP-пакетов для стабильного прохождения рукопожатий через промежуточные сетевые узлы. После начальной обработки соединения TCP-потоки передаются по обычному пути в ядре без накладных расходов на шифрование и проксирование.

## Обязательные поля

| Поле | Тип | Описание |
|---|---|---|
| `type` | string | Значение `desync`. |
| `tag` | string | Имя объекта. По нему ссылаются `route.rules`, `dns.rules`, `detour` и группы. |

## Поля TCP-сегментации

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `preset` | string | `"fake_split"` | Профиль параметров: `fake_split`, `fake_disorder`, `multi_disorder`, `multi_split`, `split`, `disorder`, `tlsrec`, `fake`, `oob`, `disoob`, `auto` (`adaptive`, `smart`, `discord`). |
| `mode` | string | `"fake_split"` | Режим сегментации TCP: `none`, `split`, `disorder`, `fake`, `fake_split`, `fake_disorder`, `multi_split`, `multi_disorder`, `tlsrec`, `oob`, `disoob`, `tlsspoof`. |
| `auto_tune` | boolean | `false` *(вкл. для не-loopback, если не задано явно)* | Адаптивный подбор рабочей стратегии для TCP и UDP при сетевых сбоях. |
| `fooling` | string | `"md5"` | Модификация decoy TCP-сегментов: `md5`, `badsum`, `badseq`, `badack`, `ts`, `hopbyhop`, `none`. |
| `split_pos` | string / integer | `"midsld"` | Позиция разреза TCP: число байт либо `sni`, `sni_ext+1`, `host+1`, `midsld-2`, `midsld`, `midsld+2`, `endhost-1`, `extlen` (а также массив позиций в режиме `multi_*`). |
| `seqovl` | integer | `0` | Перекрытие TCP sequence numbers (`0..=256`). |
| `syndata` | boolean | `false` | Включать начальные данные в `SYN` через TCP Fast Open. |
| `host_fake` | boolean | `false` | Подстановка decoy-сегментов с альтернативным `Host`. |
| `wsize` | integer | `0` | Начальное окно приёма TCP (`SO_RCVBUF` / window clamp). |
| `wscale` | integer | -- | Показатель TCP Window Scale (`0..=14`); также принимается алиас `scale`. |
| `ipfrag` | boolean | `false` | IP-фрагментация decoy-пакетов. |
| `fake_ttl` | integer | `6` | Значение TTL/Hop Limit decoy TCP-пакетов (`1..=128`). |
| `fake_sni` | string | `"www.google.com"` | Имя SNI внутри decoy TLS ClientHello. |
| `sni_pool` | array of string | -- | Список доменов SNI; используется первый непустой элемент, если `fake_sni` не задан. |
| `fake_payload` | string | -- | Пользовательский TCP decoy-буфер (hex `0x...` или строка); также принимается алиас `fake_tls`. |
| `repeats` | integer | `1` | Число повторов decoy TCP-сегментов (`1..=100`). |
| `split_delay_ms` | integer | `1` | Пауза между TCP-сегментами в миллисекундах (`0..=1000`). |
| `tlsrec_first` | boolean | `false` | Дополнительное разбиение первой TLS-записи. |

## Поля UDP и QUIC

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `udp_fake` | boolean | `true` | Отправка предварительных decoy UDP-пакетов. |
| `udp_repeats` | integer | `3` | Число UDP decoy-пакетов в серии (`1..=50`). Если задано явно или задан `udp_out_range`, `auto_tune` не увеличивает это значение. |
| `udp_fake_ttl` | integer | `6` | TTL/Hop Limit для UDP decoy (`1..=128`). При отсутствии явного значения калибруется по оценке числа хопов до адреса назначения. |
| `udplen` | integer | `0` | Длина дополнительного padding в байтах (`0..=256`) для встроенных UDP decoy-генераторов. |
| `udp_fake_payload` | string | -- | Однозначный HEX-буфер для UDP decoy (допускается префикс `0x`/`0X`, без пробелов, чётная длина, декодированный размер `1..=1472` байт). Передаётся без изменения длины с обычной обработкой UDP/IP. |
| `udp_out_range` | integer / string | -- | Включительный 1-based диапазон номеров оригинальных исходящих UDP-датаграмм в логическом потоке (`N` означает `1..=N`, либо строка `"start-end"` / `"start:end"` в пределах `1..=256`). Перед каждой оригинальной датаграммой из диапазона отправляется серия fake-пакетов; далее идут только оригинальные датаграммы. |
| `udp_keep_socket` | boolean | `false` | Политика восстановления UDP-сокета при отсутствии встречных пакетов. При `true` отсутствие ответного трафика само по себе не закрывает активный исходящий UDP-сокет и не ротирует порт. |
| `quic_desync` | boolean | `true` | Включение специальной обработки для трафика QUIC на UDP-порту `443`. |
| `quic_repeats` | integer | `0` (`udp_repeats`) | Отдельное число повторов для UDP `443` (`1..=50`). |

### Кодирование и приоритеты `udp_fake_payload`

1. `udp_fake_payload` принимает только валидную HEX-строку (необязательный `0x`/`0X` и чётное число `[0-9a-fA-F]`), декодированную длину `1..=1472` байт. Пустая строка, нечётная длина, посторонние символы, нестроковый тип или размер свыше `1472` байт отклоняются при `tachyon-core check`.
2. При заданном `udp_fake_payload`:
   - его декодированные байты имеют строгий приоритет над встроенными генераторами decoy (`QUIC Initial`, `STUN`, `Discord IP Discovery`, непрозрачные буферы);
   - поле `udplen` и адаптивное добавление padding полностью игнорируются — длина пакета точно равна декодированному `udp_fake_payload`;
   - `auto_tune` никогда не подменяет `udp_fake_payload` и не включает поверх него адаптивное искажение checksum или адаптивную IP-фрагментацию.

### Взаимодействие с `auto_tune`

- Явно заданные параметры пользователя не переопределяются алгоритмом `auto_tune`:
  - `udp_fake_payload` всегда используется дословно;
  - `udp_out_range` всегда задаёт точные границы отправки серий;
  - явно указанные `udp_repeats`, `udp_fake_ttl` и `udp_keep_socket` сохраняются неизменными.
- Если `udp_out_range` задан, переоткрытие исходящего UDP-сокета (при ротации по умолчанию или после сетевой ошибки) в рамках активного логического потока не запускает заново уже пройденные номера датаграмм и исчерпанный диапазон. Счётчик сбрасывается только при завершении логического потока по `udp_timeout`, явном закрытии соединения через Clash API, изменении конфигурации или остановке инбаунда.

### Разграничение `udp_keep_socket` и `udp_timeout`

- `udp_keep_socket` управляет **политикой восстановления при отсутствии встречного трафика**:
  - `false` (по умолчанию): если от удалённого узла нет ответа, движок закрывает исходящий сокет через ~`2 с` на старте (либо через два окна по `4.5 с` при безответной передаче `>= 256` байт для не-голосовых потоков), чтобы переоткрыть сокет с новым портом и следующей стратегией.
  - `true`: отсутствие ответных пакетов при живом потоке не закрывает исходящий UDP-сокет и не меняет его внешний порт.
- `udp_timeout` (в `route-options` или профиле инбаунда, по умолчанию зависит от ОЗУ — `30..180 с`) управляет **таймаутом простоя логического потока**:
  - при полном отсутствии как исходящих, так и входящих датаграмм дольше `udp_timeout` логический поток завершается и сокет закрывается даже при `udp_keep_socket: true`.
- Кроме `udp_timeout`, при `udp_keep_socket: true` сокет по-прежнему штатно закрывается при:
  1. явной ошибке сокета на чтении или записи (например, `ECONNREFUSED`, `ENETUNREACH`, `EHOSTUNREACH`, `EPIPE`);
  2. закрытии соединения через Clash API или ревалидации маршрута при перезагрузке конфигурации;
  3. срабатывании лимитов числа UDP-сессий (`udp_nat_max_sessions`) или дефиците памяти.

## Общие поля

Поддерживаются поля диалера ([dialer](../common/dialer.md)) и базовые опции прямого соединения (`override_address`, `override_port`, `proxy_protocol`).

## Пример для игрового UDP-диапазона

```json
{
  "outbounds": [
    {
      "type": "desync",
      "tag": "udp-game",
      "mode": "fake",
      "auto_tune": false,
      "udp_fake": true,
      "udp_repeats": 6,
      "udp_fake_ttl": 64,
      "udp_fake_payload": "0x000100002112a442b7e7a701bc34d686fa87dfae",
      "udp_out_range": "1-2",
      "udp_keep_socket": true
    }
  ],
  "route": {
    "rules": [
      {
        "action": "route",
        "network": "udp",
        "port_range": ["30000:30099"],
        "outbound": "udp-game"
      }
    ]
  }
}
```
