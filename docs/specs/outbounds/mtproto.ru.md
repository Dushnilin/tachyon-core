# MTProto Outbound

Обфусцированный MTProto-прокси для маршрутизации трафика Telegram через прокси-сервер.

## Схема

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `type` | string | — | Должно быть `"mtproto"` |
| `tag` | string | — | Уникальный тег исходящего соединения |
| `server` | string | — | Адрес прокси-сервера (хост или IP) |
| `server_port` | integer | — | Порт прокси-сервера |
| `secret` | string | — | Секрет MTProto-прокси. Hex-строка с префиксом `ee` для режима FakeTLS или `dd` для режима obfs2. Допускается base64-кодировка. |
| *(dial fields)* | — | — | Стандартные поля набора соединения (`detour`, `bind_interface` и др.) |

## Пример

```json
{
  "type": "mtproto",
  "tag": "mtproto-out",
  "server": "proxy.example.com",
  "server_port": 443,
  "secret": "ee1234567890abcdef1234567890abcdwww.google.com"
}
```

## Примечания

- Секреты с префиксом `dd` используют режим обфускации **obfs2**.
- Секреты с префиксом `ee` используют режим **FakeTLS** — соединение имитирует TLS-трафик к домену, вписанному в секрет (после 32-байтного hex-ключа). FakeTLS настоятельно рекомендуется для обхода DPI.
- Этот outbound полезен исключительно для трафика Telegram. Настройте правила маршрутизации для диапазонов IP Telegram (например `91.108.0.0/16`, `149.154.0.0/16`) с направлением в данный outbound.
- Прокси-сервер должен быть совместимой реализацией MTProto-прокси (например MTProxy, mtg).
